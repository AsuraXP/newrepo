# WORKFLOW — how a video gets made in this repo

> Generic production manual. No story, no episode, no continuation — this is the
> machinery only. Paste the block below into a fresh chat and start a new video
> from zero.

---

## Paste this into a new chat

```
I make narrated video essays / animated story videos in a repo called AsuraXP/newrepo (branch: whatever Arena gives me). I want to start a NEW video from scratch. You are my production pipeline. Read this whole thing first, then check the repo, then confirm in 3 lines what you understood before doing any work.

=== THE PIPELINE, END TO END ===
Final output = one MP4 (16:9, 1376x768, 30fps, h264+aac) + a thumbnail + a zip.
Everything lives in examples/<slug>_video/ where <slug> is short and lowercase, e.g. apoc_day1.

Stage 1. SCRIPT
Write the narration first, in full, as plain text, and show it to me for approval before ANY images. Second person / present tense / played straight if it's fiction. No channel name, no character names, no on-screen text. I read it and I will tell you what to change.

Stage 2. visuals.csv  (the spine of the whole thing)
One row per image moment:
  slide_id,moment,moment_text,visual_prompt
- slide_id = the beat number (1, 2, 3 ...). A beat is one scene/turn in the story.
- moment = order within the beat (1, 2, 3 ...).
- moment_text = the exact words of the narration spoken under that image. Keep it to ONE sentence. Word-locked cuts come from this.
- visual_prompt = what the image model is told to draw.
Aim for roughly 4-6 seconds of narration per image moment. 5:00 of video at ~2.75 words/second is about 800-900 words and 90-120 moments.

Stage 3. beats.jsonl
  python3 -m cartoonstyle.csv_to_beats --visuals visuals.csv --out beats.jsonl
Groups consecutive rows into one beat per slide_id.

Stage 4. sfx.csv  (optional, single voice only)
key,sfx,offset
beat02m01,knock x3,0
beat07m01,ring,0
There is no voices.json and no multi-voice any more: one narrator, one continuous take.
sfx.csv anchors a sound to an IMAGE MOMENT, not a hand-counted second. tts resolves it
against moments_timing.json and writes sfx_cues.csv in absolute seconds, so the sound
lands on the cut at any speaking rate. Cues: knock, knock x2, knock x3, thud, click,
rumble, ring, steps (add more to RENDER in cartoonstyle/sfx.py).

Stage 5. TIMING (two modes)
  # sandbox: no internet, no real voices. Estimates timing from word count.
  python3 -m cartoonstyle.tts --beats beats.jsonl --out-dir . --visuals visuals.csv --simulate
  # Kaggle: real edge-tts audio
  python3 -m cartoonstyle.tts --beats beats.jsonl --out-dir . --visuals visuals.csv --voice en-US-AndrewNeural
Outputs beats_with_timing.json (one audio file per beat) and moments_timing.json (exact seconds per image, word-locked) and sfx_cues.csv.

Stage 6. SFX
  python3 -m cartoonstyle.sfx --cues sfx_cues.csv --out sfx.wav --gain 0.9
Fully synthesized with the standard library — no asset files, no licences. Add new sounds in SOUNDS inside cartoonstyle/sfx.py.

Stage 7. IMAGES
One image per moment, generated by the image model, saved into frames/ as beat{NN}m{NN}.png (zero-padded), e.g. beat05m03.png.
Then they must be placed in a pool with the stitcher's naming:
  beat{NN}m{NN}_v00_s00000.png
(That pattern is {key}_v{pick:02d}_s*.png — the stitcher globs it. Symlink or copy, don't rename the originals.)
Every image MUST be 16:9 landscape and MUST be resized to exactly 1376x768 before stitching. The image model returns whatever size it likes (often 1672x941) — normalise with PIL LANCZOS, never crop, never stretch.

Stage 8. STITCH
  python3 -m cartoonstyle.stitch --timing beats_with_timing.json --images-dir pool --out VIDEO.mp4 --pick 0 --sfx sfx.wav
Useful flags: --captions (word-locked subtitles, --caption-method ass|pil), --qc qc.jsonl, --fps 30, --no-loudnorm (audio is normalised to -14 LUFS by default).

Stage 9. DELIVERABLE
On Kaggle: !bash newrepo/run_video_kaggle.sh <slug>
It picks up examples/<slug>_video/ automatically, synthesizes one continuous take, mixes sfx if sfx.csv exists, stitches, and writes $OUT_DIR/<slug>_DELIVERABLE.zip. Env overrides: VIDEO_DIR, OUT_DIR, VOICE, RATE, SKIP_TTS=1, ZIP_NAME, CAPTIONS=1, BRAND_WORDS.
IMPORTANT: that script's header documents cloning https://github.com/AsuraXP/CartoonStyle.git — check the clone URL and branch actually match the repo you pushed to, and fix it if not.

=== SANDBOX GOTCHAS (learned the hard way) ===
- No system ffmpeg, no ffprobe, no PIL. Install once:
  pip install pillow imageio-ffmpeg --break-system-packages
  Modules fall back to imageio_ffmpeg.get_ffmpeg_exe().
- edge-tts does NOT work in the sandbox. Real narration only happens on Kaggle. Use --simulate locally and check the runtime math.
- Set PYTHONPATH=/home/user/newrepo so `python3 -m cartoonstyle.*` resolves.
- find_image() silently skips any frame whose filename doesn't match. If a beat is missing from the video, the filename is wrong.

=== IMAGE GENERATION RULES ===
- HARD CAP: 10 images per turn. Plan batches around it. Never burn all 10 on a single shot.
- THE RULE THAT MATTERS MOST: each image must literally illustrate its own moment_text. Count the people the sentence mentions and draw exactly that many. Match the action, the direction of gaze and the location to the words. Never invent a cooler composition than the sentence asks for.
- Put a fixed style block at the START of every prompt so the look stays consistent, then the character/object spec, then the scene. Write it once and reuse it verbatim.
- NO TEXT IN IMAGES. No letters, numbers, signage, logos, watermarks, and nothing printed on any surface. If the story needs a screen or a page, describe abstract bars, bubbles and chips instead.
- Negative-stacking does not work. If a prompt returns a diagram or the wrong thing, rewrite the SHOT DESCRIPTION.
- Recurring characters need an explicit spec every time (shape, colour, exactly how many eyes, what they wear, "red is the only colour in frame"). Vague = drift.
- A cast shadow can produce a second figure. Say "only one person in this frame" when it matters.
- Violent action wording gets blocked by moderation. Describe threat as presence and posture, not as impact, collapse or wounds.

=== QC LOOP (every batch) ===
1. Generate 10.
2. Build a contact sheet with PIL (5 cols, ~380px thumbs, label with batch name and count).
3. LOOK at the sheet. Pick the rejects.
4. Re-roll rejects first in the next batch.
5. Commit and push after each batch: git add -A && git commit -m "<slug>: batch N - <what>" && git push
6. Give me a SHORT report: what worked, what got re-rolled and why. No essays.
Commit every 8-16 verified frames so nothing is ever lost.

=== THUMBNAIL ===
AI-generated, with all type baked in by the image model itself. Never stamp text over it with PIL. No fonts layered on top afterwards.

=== HOW I WANT US TO WORK ===
- Show me the full narration text and let me read it BEFORE generating any images.
- Don't ask me to preview or watch renders mid-run. "No need to trim", "just continue".
- Batch → QC sheet → commit → short report. That's the loop.
- No channel name, no character names, nothing branded, in the video or its metadata.
- Fiction is played completely straight: no statistics, no cited studies, no "here's the science".
- One day / one problem / one decision per episode if it's episodic.
- Never push to a branch other than the one the session is on.

=== MY FIRST ASK ===
I'll tell you the new video's premise. Then:
1. Write the narration and show it to me. Wait for my go.
2. Build visuals.csv (+ sfx.csv), run stages 3-6 with --simulate, and tell me the exact runtime.
3. Then start images, 10 per turn, QC sheet after each batch.
```

## Files this workflow depends on

| Path | What it is |
|---|---|
| `cartoonstyle/csv_to_beats.py` | `visuals.csv` → `beats.jsonl`, one beat per `slide_id` |
| `cartoonstyle/tts.py` | the only voice path: one continuous take, word-locks moments, resolves sfx.csv, `--simulate` for sandbox runs. Keep the forward-moving `pos` cursor, it fixes a beat-matching bug |
| `cartoonstyle/sfx.py` | procedural knock/thud/click/rumble, stdlib only |
| `cartoonstyle/stitch.py` | word-locked cuts, optional burned captions, loudness normalisation, `--sfx` mix |
| `cartoonstyle/align.py` | faster-whisper forced alignment of an existing narration track |
| `cartoonstyle/plan.py` | pacing + script-coverage gate before any image is generated |
| `cartoonstyle/prep_frames.py` | `frames/` → `pool/` at exactly 1376×768; `--check` gate |
| `cartoonstyle/contact_sheet.py` | QC sheet, `--visuals` prints each `moment_text` under its tile |
| `run_video_kaggle.sh` | one-shot Kaggle build → `<slug>_DELIVERABLE.zip` |

The old `tools/` scripts (`make_thumbnail.py` and friends) are deliberately not carried
over: the thumbnail is AI-generated with type baked in, and the rest were one-off
episode helpers.

## Worked numbers from a real 5:04 build

- 29 beats · 122 moments · 778 words · 4:42 at 2.75 words/sec planning pace, 5:04 as stitched.
- 7 sfx cues. 3 voices. 1376×768 at 30fps, h264 + aac.
- 122 frames rendered over 13 batches of ~10, one contact sheet per batch.

# CORRECTIONS — verified against the code on 2026-10-27

The brief above is the source of truth for *intent*. These are the places where the
written numbers and the actual modules disagreed, checked by running them.

## 1. "4-6 seconds per image" and "90-120 moments" cannot both be true

At 2.75 words/sec:

| moment length | words per `moment_text` | moments for 5:00 |
|---|---|---|
| 2.5 s | ~7 | 120 |
| 3.3 s | ~9 | 90 |
| 4.0 s | ~11 | 75 |
| 5.0 s | ~14 | 60 |
| 6.0 s | ~16 | 50 |

90-120 moments is a **2.5-3.3 s cut**, i.e. 20-24 images per minute. 4-6 s per image
is 50-75 images for a 5:00 film. Both are defensible; they are not the same film.
Decide per episode before writing `visuals.csv`, because it sets the image budget
(10 per turn) and therefore the schedule.

## 2. Stage 6 is conditional

`sfx` exits with a clear message when `sfx_cues.csv` does not exist, and that file is
only written when the episode has a non-empty `sfx.csv`. Run it only if the file is there.

## 3. `--simulate` is not offline

`tts --simulate` builds its silent take by shelling out to ffmpeg. Without a binary it dies
with `FileNotFoundError: 'ffmpeg'`. `pip install imageio-ffmpeg` is mandatory even for
a simulated dry run; the modules fall back to `imageio_ffmpeg.get_ffmpeg_exe()`.

## 4. The stitcher never resized anything

It used to compute `canvas = largest frame in the pool` and paste smaller frames at
(0,0) on black. One 1672×941 image made the whole video 1672×942; one 1365×768 image
put an 11 px black stripe on its right edge. Now:

* `stitch --canvas 1376x768` (default) locks the output size;
* anything that is not already that size is LANCZOS-fitted and letterboxed in its own
  edge colour, never cropped, never stretched, and flagged in the log;
* `python3 -m cartoonstyle.prep_frames --frames frames --out pool` is the intended fix,
  and `--check` exits 1 as a pre-encode gate.

## 5. `SKIP_TTS=1` used to re-run TTS

The flag used to skip the pip install and then still run the TTS module, which crashed
on `import edge_tts`. The runner now skips the stage entirely and verifies that
`moments_timing.json` covers every row of `visuals.csv` instead.

## 6. Multi-voice was silently single-voice on Kaggle

`run_video_kaggle.sh` computed `TTS_MODULE=cartoonstyle.tts_multi` and then called
`python3 -m cartoonstyle.tts` on the next line, so a `voices.json` would have been passed
to a module with no `--voices` flag. Moot now that multi-voice is removed, but it is why
the earlier episodes are all single-voice in practice.

## 7. Clone URL

The runner header documented `github.com/AsuraXP/CartoonStyle.git` (a different,
now-empty repo). It is `github.com/AsuraXP/newrepo.git`, with `--branch <session-branch>`.

## 8. `--qc qc.jsonl` is dead

It reads a file produced by `cartoonstyle.qc`, which does not exist in this repo.
The flag is harmless and does nothing. Use the contact-sheet loop instead.

## 9. Packaging

The preflight demanded `script.md`, `metadata.json` *and* `youtube.txt`, none of which
the pipeline produces. It now needs `visuals.csv`, `frames/`, a `thumbnail.*` and a
`title_description.txt` (or `youtube.txt`), and packages exactly the video + thumbnail
+ that text file into `<slug>_DELIVERABLE.zip`.

## 10. Runtime estimate accuracy

`plan` estimates from word count at the `--wps` you pass; `--simulate` uses exactly
2.75. A real edge-tts take at `-6%` runs about 3-6% longer, and punctuation adds pauses
the estimate ignores. Quote a range (±5 s on a 5:00 film) until the Kaggle pass has run,
then re-measure `narration.mp3`.

## 11. Typo in the brief

`момент_text` in stage 2 is `moment_text` (Cyrillic м и е sneak in from a keyboard
layout). The CSV header must be ASCII or `csv_to_beats` will not find the column.

# SINGLE VOICE — 2026-10-27

Multi-voice is gone. `cartoonstyle/tts_multi.py` is deleted, `voices.json` is no longer
read by anything, and the runner calls `cartoonstyle.tts` unconditionally: one voice,
one continuous take, clean prosody, no per-beat gluing.

What replaced the one thing tts_multi was genuinely better at (sfx timing): **word-anchored
cues**. `sfx.csv` in the episode folder is `key,sfx[,offset]`, where `key` is an image
moment key like `beat05m03`. `tts` resolves each row against `moments_timing.json` and
writes `sfx_cues.csv` in absolute seconds. The knock lands on its cut at any speaking
rate, and there is no frame where the cue and the cut disagree.

Cues available: `knock`, `knock x2`, `knock x3`, `thud`, `click`, `rumble`, `ring`, `steps`
(add more in `RENDER` in `cartoonstyle/sfx.py`).

`tts --simulate` now exists, so the sandbox can produce a timing-accurate silent take:
`python3 -m cartoonstyle.tts --beats beats.jsonl --out-dir . --visuals visuals.csv --simulate`
